# 钱迹个人网页版与 MCP 服务设计

- 日期：2026-10-18
- 状态：架构及需求基线已在对话中确认；本文待书面审阅
- 修订：依据用户要求补查 APK 的冲突处理，普通同步采用官方结果自动收敛，区分 ID 冲突与多端编辑
- 目标客户端：钱迹 Android 4.5.4，versionCode 1234
- 部署方案：Cloudflare Workers Paid + D1 + 一个逻辑上的 Durable Object 协调器

## 1. 目标与已确认约束

为一个人提供完整的钱迹网页版和可接入 ChatGPT 的远程 MCP 服务。网页与 MCP 共用业务规则、数据副本、钱迹连接和同步任务，尽量覆盖 APK 中适合这两种交互方式的账务功能。

用户已确认：

1. 只有一个服务使用者、一个当前连接的钱迹账号，不建设多用户注册、租户或权限体系。
2. 应用页面和 MCP 均不增加访问认证，不建设 PAT、OAuth、一次性连接票据；入口保护由用户配置 Cloudflare。
3. 钱迹登录仅支持手机号或邮箱加密码，不实现微信、Apple 等第三方登录。
4. 提供完整网页版；MCP 与网页具有对应的业务能力，但交互组织分别适配自然语言和页面操作。
5. 完整功能和可靠性优先。已选择 Workers Paid + D1 + 单个 Durable Object 的方案，不围绕 Workers Free 的 CPU 限制裁剪功能。
6. 使用时按需更新。闲置且没有用户发起的在途任务时，不向钱迹发起请求，不做周期性后台轮询。
7. 普通查询使用 60 秒数据新鲜期；同步任务共享、合并。60 秒为本服务已确认的默认值，不是从 APK 得出的常量。
8. 保留登录、线路选择、登录状态维护、手动同步和同步诊断等必要服务管理功能。
9. 不复制 APK 的系统及个性化设置，不提供数据导出；排除手机专属能力与不适合本项目的账户管理功能。

成功标准：用户可以在网页或 ChatGPT 中查询、分析并管理钱迹数据；网页、MCP 和官方客户端的账务结果一致；跨设备变化能在使用时获取；并发调用、任务中断和网络异常不会产生重复记账或虚假的成功结果。

| 图片附件 | 图片展示、上传、附加、移除，关联到对应账单或支持图片的业务 | 上传凭证、资源地址、有效期、失败补偿、上游数量限制 |

| 服务管理 | 账号连接、状态检查、刷新登录状态、重新登录、退出、线路选择及按需测试、手动增量/全量重建、任务和操作结果查看 | 固定设备标识、无后台保活、凭证失效与写入结果不明的区分 |

不纳入：

- 数据导出、客户端下载与版本更新、账户注册注销和改密、第三方账号绑定、会员购买、意见反馈等官方客户端配套流程。
- Android 通知监听、无障碍读取支付页面、悬浮窗、短信监听、桌面组件、系统权限和启动优化。
- 完整 APK 外观、主题、字体、振动、应用锁等个性化或系统设置。
- 自动读取其他手机应用、抓取银行账号、另外建设 AI/OCR 服务、独立的手机配套程序。
- 备份导出和迁移向导等产品界面。数据库运行维护仍采用 Cloudflare 原有工具。

ChatGPT 可通过其已有图片理解能力组织记账参数；本项目不为此新增模型调用或模型 API 费用。网页图片附件功能仍在范围内。

## 4. 架构与模块职责

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| 网页 | React、TypeScript、Vite 构建的中文响应式应用，通过 Workers Static Assets 发布 | 使用业务 HTTP API，不直接持有或请求钱迹 token |
| HTTP API | 提供页面查询、操作、连接和任务状态接口 | 负责输入输出转换，不重复实现账务规则 |
| MCP | `/mcp` 提供 Streamable HTTP、工具说明、结构化结果和任务状态 | 使用适配 Workers 的传输实现；业务状态不依赖单个 HTTP 会话 |
| 领域服务 | 账单、资料、资产债务、预算统计、周期分期、储蓄、附件等独立模块 | 网页和 MCP 调用同一用例及校验；不暴露任意 SQL 或任意上游路径代理 |
| 钱迹适配器 | 签名、画像、请求编码、无损 JSON、响应及错误归一化 | 私有协议集中维护；版本更新不蔓延到页面和工具 |
| 单个协调器 | 一个固定名称的 Durable Object，协调上游请求、同步合并、写入次序、设备和签名时序 | 一个逻辑对象即可，运行时由 Cloudflare 按需唤醒；不建设多账号对象分片 |
| D1 | 已发布数据副本、资料、操作日志、同步进度、原始字段和连接配置 | 是本地查询数据库；钱迹云端为账务权威来源 |

协调器显式实现队列及恢复状态，不能只依赖进程内 Promise、Map 或单次对象生命周期。跨 `await` 的任务顺序与互斥需要显式设计。D1 与 Durable Object 存储间不假定存在共同事务；业务结果和发布进度以 D1 持久记录为准，协调状态可据此恢复。

默认不引入 Cron、Queues、常驻 WebSocket 或另一台服务器。用户发起的长同步允许通过协调器的持久任务及按需 alarm 续跑；任务终止后取消续跑。alarm 可能重复执行，恢复逻辑必须先核对持久状态，不能因此重复提交钱迹写请求。

图片上传首先沿用钱迹的上传与存储机制，不把图片二进制存入 D1。若上游协议确需中转暂存，再增加 R2，并在实现前记录用途、生命周期和费用影响；R2 不是基础方案的强制依赖。

## 5. 登录、凭证和线路

1. 网页服务管理入口接收手机号或邮箱及密码，依照核对后的 APK 协议完成当次登录。密码及可重放的密码摘要均不持久化，不进入 MCP 参数或日志。
2. 保存 UID、稳定设备 ID、必要用户配置及加密 token。加密密钥来自 Worker Secret；部署更新和实例重启后仍能恢复连接。
3. 同一 UID 重新登录保留数据副本及设备 ID，更新 token。返回不同 UID 时不得把数据并入旧账号，必须显式重建连接和本地缓存；不影响钱迹云端数据。
4. 登录状态检查、手动刷新和普通调用复用同一状态机：已连接、检查中、需重新登录、协议异常、网络异常。网络或签名失败不能一律误报“密码失效”。
5. 令牌刷新先完成协议及实测验证；如条件允许，可在使用时合并执行一次刷新并重试只读请求。刷新失败进入重新登录状态，不循环重试，不为了保活定时请求。
6. 任何写操作若存在“钱迹可能已收到”的情况，登录刷新后也先核查操作结果，不直接重新提交。
7. 提供默认、备用、海外线路选择。默认使用已核对的主线，不后台自动测速或主动切线。用户点击测试时从 Worker 出口发起有限的只读检查。
8. 切线保留设备 ID、游标与操作记录；若线路不接受当前连接，明确提示重新登录，不清除已确认的账单数据，不重发结果不明的写操作。

页面与 MCP 的“免认证”指本服务的访问方式；连接钱迹账号是独立业务流程。Cloudflare 入口规则需允许 ChatGPT 的 MCP 请求通过，该连通性纳入验收。

## 6. 按需同步与数据发布

### 6.1 触发和缓存

| 情形 | 行为 |
| --- | --- |
| 首次登录且没有副本 | 启动首次全量同步；页面显示进度，MCP 返回可查询的任务信息 |
| 打开网页或调用普通查询，最近一次相关数据成功发布不超过 60 秒 | 使用 D1，不为同一数据再发起上游同步 |
| 相关数据超过 60 秒 | 合并到已有同步，或发起一次增量同步 |
| 统计/查询依赖全量完整性 | 等待发布；若不能在请求期限内完成，返回任务状态或明确标记的旧快照，不能把旧值说成最新值 |
| 多页面、多标签页或多个 MCP 并发调用 | 共享一个相关同步任务，不按调用次数复制上游请求 |
| 浏览器重新聚焦 | 检查相关数据新鲜度，遵循同一规则，不无条件刷新 |
| 用户明确要求刷新 | 绕过 60 秒缓存新鲜期；保留队列和冷却约束，重复点击合并 |
| 写入后 | 优先使用回执及针对性回拉完成核验，刷新受影响缓存，不默认再做全量同步 |
| 闲置且无在途任务 | 不向钱迹请求，也不以保活、测速或令牌维护为由访问上游 |

网页可在任务进行时查询本服务的进度，这不触发另一轮钱迹同步。数据返回包含同步时间、快照版本和是否陈旧；失败时页面可继续显示旧数据并提示，MCP 必须传递相同的新鲜度信息。

普通账单同步入口继承 APK 已确认的 5 秒完成后冷却。60 秒缓存规则通常会减少触发次数；手动刷新也不会通过建立多个任务来绕过冷却。写后核验为在途操作的一部分，由协调器安排，不让普通冷却把已发生的写入误判为失败。

账本、分类和成员优先采用初始化和同步下发的数据。用户资料、资产、预算、币种、周期、分期等域只在当前用例需要时补取；各域以最近成功获取时间及失效标记控制缓存，不在每轮账单同步中刷新所有资源。普通在线查询仍以 60 秒作为默认新鲜期，保存写入后立即使受影响域失效。

### 6.2 增量和完整性

- 首次/重建按核对后的协议从初始游标开始；普通轮次使用钱迹返回的按账本 `lasttimes`。分页回传真实 `bookid/pageoffset/pagesign`，不猜测或自行生成分页状态。
- 一轮同步固定起始 `lasttimes`，合并新增、修改、删除、分类变化；标签使用其独立协议和游标。不同数据域独立标记成功时间，不把标签成功视为账单成功。
- 每页持久化进度，D1 使用有限批次；同步的数据与最终游标在完整轮次成功后共同发布，不暴露半轮结果。
- 每个可独立同步的数据域采用版本化记录、代次状态与已发布指针：新代次记录先写入 D1，读请求固定使用已发布代次；最后通过小型 D1 事务将该代次标记为已发布，同时更新发布指针、最终游标和任务状态。删除以对应代次的删除标记表达；账单同步一并下发的分类在同一代次发布。
- 查询每个 ID 在固定快照内、属于成功发布代次的最新版本；失败或废弃代次始终不可见，不能仅以“代次号不超过发布指针”判断可见性。旧版本清理保留有效分页游标所需的数据。分页游标有效期设为 15 分钟，过期明确返回重新查询提示，不在版本清理后悄悄切换数据集。
- 全量重建使用独立数据集，保留原数据集直到新数据集完成并切换指针；新集合不继承旧集合中未再次出现的记录。重建失败时旧快照和旧最终游标仍可查询，旧数据集保留至引用它的分页游标过期。
- 可用的上游分页令牌按实际验证结果续用；若令牌失效，则从上一轮已发布游标重新开始，不假定令牌无限期有效。
- 用户发起的在途任务在关闭页面后可以完成；它结束后不自行再安排下一轮同步。

## 7. 写入、同步收敛与结果核查

所有钱迹变更都由协调器执行，并持久化操作记录。操作状态包括：排队、发送中、核验中、已确认成功、已确认失败、结果待核查、部分成功。

普通同步按 APK 的已确认行为自动应用钱迹回执和下发记录，不为每次数据变化增加通用的三版本选择弹窗。D1 已发布副本与编辑草稿、待提交操作分别存储；草稿和操作记录不会因副本刷新而丢失，也不参与已确认账务的统计。两端同时修改时最终采信哪次提交，以官方服务的实际回执和回拉结果为准，不能仅从客户端替换本地行的行为推导为“最后提交必胜”。

1. 网页自动生成稳定 `requestId`；MCP 写工具要求相同用途的请求键。请求键与规范化参数摘要一起保存：同键同参数返回既有结果，同键不同参数拒绝执行。
2. 记录目标、原始版本、计划变更及必要的新记录 ID，再将状态持久化为发送中，之后才访问钱迹。
3. 同账号的同步发布与写入按序执行。提交时先读取最新目标，按用户本次明确的变更构建载荷并校验业务前置条件。版本信息用于识别陈旧草稿和保留诊断，不把单纯更新时间变化一律转成人工版本选择。目标已删除、类型或关联关系变化使操作不再适用时，返回具体业务原因并保留草稿。是否存在可用的上游条件写入仍需核验，不承诺跨设备强一致锁或完全消除覆盖风险。
4. 核对 HTTP、业务错误码和业务回执中的逐项接受、拒绝及删除结果；按已核对的 APK 语义处理 `conf_ids`，不把它解释为通用编辑版本冲突。成功后按操作类型回拉，核查账本、金额、时间、分类、资产、关系和关键扩展字段。
5. 明确业务拒绝可记录失败；网络中断、进程重启、缺失回执、回拉超时或字段不符均不能自动视为未执行。
6. 结果待核查时只做读取核验。可查询、刷新和处理无关数据；对相同目标及其关联数据的后续变更暂缓，避免扩大不确定性。
7. 批量操作记录逐项状态，已确认成功项不会因其他项失败而重发；钱迹不支持远端事务时，不承诺整批回滚。
8. 不根据金额、备注相同就自动合并或删除账单；重复候选只是辅助信息。写键负责请求重放，业务查重负责提示，二者分开。
9. 删除明确指定对象和关联处理策略，不默认级联。网页展示删除影响，MCP 提供破坏性提示和明确参数；已明确表达的请求不额外增加无意义的多轮确认。
10. 报销迁移等账号级不可逆变化不自动触发；如当前业务必须执行，先呈现具体影响，由用户明确决定。

实际录入按钱迹确认结果回填 UI。保留待核查状态和操作入口，不以页面乐观更新或 MCP 文本描述替代上游确认。

账单新建 ID 冲突单独处理：只有本次新增已收到明确拒绝回执、且其语义核对为 APK 对应的 ID 冲突时，才生成新 `billid` 并持久化尝试和 ID 映射，按有限批次继续上传；原 `requestId` 不变。不能给已有云端记录改 ID，也不能把编辑、删除失败或网络超时一律改成新建。待提交记录之间的引用按已核对的关系更新，回拉时核验最终分配的 ID。APK 一轮最多 5 批、每批最多 200 条是已观察到的客户端上传边界；本服务使用持久任务限制每次处理量，并按逐项确认结果计算成功数量。

## 8. 数据模型与账务计算

### 8.1 持久化范围

| 数据集合 | 主要用途 |
| --- | --- |
| 连接与服务配置 | 单个当前 UID、加密凭证、设备 ID、线路、客户端协议版本 |
| 账单版本及关系 | 原始无损数据、规范化字段、删除标记、代次、退款/报销/转账/任务等关系 |
| 账本、分类、成员、标签 | 显示、筛选、业务引用、层级和对应同步状态 |
| 资产与债务、预算、币种 | 业务资料、缓存及计算依据，保留上游时间与权限信息 |
| 周期、分期、储蓄计划 | 官方任务和计划及其关联信息，不凭本地推测生成官方执行状态 |
| 附件引用 | 钱迹资源引用和必要元数据，不在 D1 保存图片二进制 |
| 同步任务、分页和发布指针 | 完整性、进度、中断恢复及游标 |
| 操作、草稿与逐项结果 | 请求去重、陈旧草稿识别、ID 冲突尝试及映射、回执、回拉核验及异常核查 |
| 能力清单 | 每项读写的协议版本、证据级别、验收状态及可用原因 |

所有业务 ID 使用十进制字符串保存及返回，包含 `-1` 等有特定语义的值；不经 JavaScript `Number` 转换。原始响应和嵌套扩展字段使用无损 JSON 解析与序列化，编辑只覆盖明确修改的字段，未知字段保持不变，不向网页或 MCP 暴露内部原始请求载荷。

金额和汇率保留十进制文本，使用精确十进制运算。经确认有固定尺度的统计金额可另存定标整数，SQL 仅在相同币种与尺度下聚合，禁止用浮点转换作为账务合计依据。超出已确认精度或金额范围的输入明确报错，不静默四舍五入。

### 8.2 统计规则

- 默认使用 `Asia/Shanghai` 解释业务日期，原始时间戳保持原值；日历、筛选和统计共用边界规则，并支持账本的自定义月份起止日。
- 类型、金额、优惠和手续费按当前 APK 的逐类型规则计算，不能对所有记录套用同一公式。
- 转账和信用卡还款独立列示；退款、报销、债务相关记录按真实关系参与对应统计，不统一归入普通收入。
- 退款的期间、分类归属以及新旧报销口径需与 APK 对照验收；在确认前明确单列，不给出声称与官方一致的错误净额。
- 多币种优先使用账单保存的历史换算信息；不使用当前汇率重写历史账单。不同币种原值不得直接求和。
- 计入收支、预算、资产等标记及自定义周期均参与计算。未知类型和未知影响字段明确列示，不假定为普通收支或零金额。
- 资产列表与独立债务接口分别建模，避免将同一债务条目重复累加；历史资产趋势优先采用已核对的官方历史数据，不能从不完整账单强行推算。
- VIP、标签数、任务数和账本可写性采用当前账号和当前 APK 已核对的规则；不把参考项目自身常量直接视作官方限制。

## 9. MCP 与网页体验

### 9.1 MCP

工具按用户任务组织：连接状态与同步、基础资料查询和管理、账单查询与统计、各类账单写入、资产债务、预算、周期分期、储蓄计划、附件、操作核查。

- 查询参数、金额、ID、分页、筛选和错误在网页与 MCP 之间保持一致。
- 写工具使用明确业务 Schema，不设计万能 HTTP 请求工具。只读、变更和破坏性注解与实际行为一致。
- 返回结构化结果及简明文字，包含数据时间、任务或操作 ID、逐项结果和下一步核查方法。
- 缺少上游连接时返回服务管理页面地址；账号密码在网页录入，不要求模型收集凭证。
- 业务工具默认最多等待 10 秒；长同步或核验未在此期限完成时，以正常 MCP 工具结果返回进行中状态和任务/操作 ID，后续调用查询既有任务，不将超时包装成“操作失败，可以重试”。
- 提供能力与状态查询，服务器使用说明明确 ID 获取、分页、金额单位、写键复用和结果待核查处理。
- 普通 ChatGPT MCP 接入使用业务工具即可；不为此强制增加通用文档搜索或 ChatGPT 内嵌 UI。

### 9.2 网页

页面包括：总览、账单与日历、统计、资产与债务、预算、周期与分期、储蓄计划、账本/分类/标签管理、服务管理。

默认中文，桌面和手机浏览器均可用。共用账本、日期和业务筛选；展示新鲜度、正在更新、冲突、待核查及不可用能力的原因。无账号时进入连接流程，无数据时显示真实空状态，不默认混入演示账单。

服务管理只保留必要连接和诊断项目。普通业务配置放在对应业务页面，不建设 APK 全部设置的副本，也不把数据库、签名或内部任务术语塞进日常记账表单。

## 10. 异常与运行维护

稳定错误类别至少包括：登录被拒绝、需重新登录、网络异常、签名或协议异常、响应结构变化、账号权益不足、资源不可写、业务前置条件变化、ID 冲突处理失败、部分成功、结果待核查、同步失败、资源用量超限。ID 冲突、用户草稿与云端变化、结果不明分别建模，不能用一个笼统“冲突”错误替代。

只读网络请求可有限重试，最多 3 次总尝试并递增等待；业务拒绝、签名错误和未知结构不做重复重试。尝试计数持久化，alarm 恢复不重置此预算。所有重试属于已发起任务，任务完成或失败后不继续安排访问。写入不复用此只读重试策略。

日志使用操作 ID 和必要诊断字段，不记录密码、密码摘要、完整 token 或整份个人账单响应。连接失效、上游协议异常、待核查操作和同步失败通过当前页面与 MCP 状态返回，不另建消息通知系统。

代码、静态资源与数据库迁移可独立升级。迁移保留操作记录、稳定设备 ID 和已发布快照，避免部署重启触发无必要的全量拉取。运行维护文档包含 Cloudflare 绑定、Secret、迁移、部署、回滚、ChatGPT 连接及用量查看；付费开通、远程部署等外部变更按实际执行时的授权处理。

## 11. 验收标准

### 11.1 协议和数据正确性

1. 对照 4.5.4 的 Java/Smali 及必要 native 逻辑核对签名、客户端画像、设备 ID、身份头、编码、接口参数及响应模型，建立逐操作证据记录。
2. 覆盖长整数、嵌套数字、精确金额、未知字段、跨币种、账单关系、自定义周期及统计排除标记。
3. 验证跨账本分页、删除、分类与标签变化、重复页、失效分页令牌、断点恢复、全量重建和失败时旧快照可用。
4. 模拟写入前后各阶段的超时和重启，证明重复调用同一写键或恢复不会重复产生业务效果；明确 ID 拒绝后的新尝试留有映射，结果不明不换 ID 重发，批量部分成功不会重发成功项。普通同步自动替换已发布副本，保留草稿及操作历史。

### 11.2 请求行为

5. 缓存新鲜期内连续查询不增加相关上游请求；并发冷查询共享一次任务；重复刷新遵守冷却和任务合并。
6. 完成在途任务后观察至少 10 分钟，钱迹请求计数不增长，且没有周期性轮询或保活触发器。
7. 切换线路从 Worker 出口验证；连接变化不导致重复写入、游标错误或账单消失。
8. 服务和协调器重启后可恢复连接和任务；待核查写入不会因 alarm 重投递而再次发送。

### 11.3 页面、MCP 和真实上游

9. 同筛选条件下网页、MCP 的账单集合、分页和金额一致；桌面与手机浏览器可以完成主要流程。
10. MCP 初始化、工具发现、Schema、注解、错误及任务跟踪可用，ChatGPT 能通过实际 Cloudflare 入口调用。
11. 使用用户指定的专用测试账本和明确测试数据逐项验收写入；先检查回执，再回拉，再在官方客户端核对。
12. 资源管理、资产债务和高级计划等不属于测试账本的操作，采用明确命名的测试对象逐项核验影响；不以测试账本的普通账单成功替代这些验收。
13. 所有交付目标在能力清单中有证据、状态和验收结果。发布说明逐项列出确实不可用的上游能力及原因，不将模拟测试通过称为真实支持。
14. 通过两端先后修改、相同及不同字段交叉修改、编辑与删除交叉、离线修改后同步、受控的新建 ID 冲突和响应丢失实验，记录服务端实际仲裁结果；不用 `conf_ids` 的本地 ID 重分配行为代替这些证据。

## 12. 实施前需要关闭的研究问题

以下是已识别的技术核验任务，处理方式和失败行为已经确定，不要求用户猜测私有协议：

| 核验任务 | 必须得到的结果 | 结果未确认时的行为 |
| --- | --- | --- |
| 新版签名的 native 部分 | 可在 Workers 中复现的算法、画像和确定性测试依据 | 不宣称新版协议已完成，不盲目只改版本号 |
| 令牌刷新 | 凭证要求、响应、有效条件及刷新后的设备行为 | 保留网页重新登录，不承诺自动永久在线 |
| 各域同步 | 真实游标、分页、删除、冲突及资源更新语义 | 保留旧发布数据，显示协议错误，不误报空账本 |
| 多端编辑与 ID 冲突 | 服务器对交叉编辑和删除的仲裁、新建 ID 拒绝语义与改 ID 后的回执 | 普通同步按官方结果收敛；不推测胜出规则，不在超时后换 ID 重发 |
| 高级资源写入 | 完整载荷、引用、权益、回执和可核查方式 | 该写能力保持未启用，仍列在交付目标 |
| 周期和分期执行 | 官方执行主体、生成条件、任务与账单关联 | 不新增 Worker 定时生成账单；可核对后的管理能力独立交付 |
| 图片链路 | 上传流程、资源引用及清理语义 | 图片写入不开放，不把链接字符串当成上传成功 |
| 新旧报销及统计 | 类型与关联模型、迁移影响及与官方报表口径对照 | 单列未确认记录，不自动账号升级，不给出伪精确合计 |

研究、协议适配、同步、领域业务、网页/MCP 和上游验收按依赖组织成实施任务；本文不把尚未研究清楚的接口提前标为可用。实施计划在本文审阅通过后另行编写。
