# 钱迹 APK 与 Web/MCP 缓存、更新策略比较

- 日期：2026-10-18
- 样本：钱迹 Android 4.5.4 / 1234，MT只读工作区`rxvx4qt6`
- 用户要求：比较当前方案与APK，选择更合适的缓存及更新逻辑；本次更新设计和计划，不实现产品。
- 方法：复核已缓存Smali，并通过MT重新读取预算时间判断、计时工具、资产列表/选择器和分期列表。未登录、未请求钱迹业务服务器、未修改APK。

## 1. 结论与选择

采用APK的本地数据优先、按页增量、领域回执更新及局部重算，同时保留本服务的60秒按需远端检查、跨Web/MCP共享任务和持久恢复。这比完全照搬APK的页面缓存时长更适合同时使用手机、Web和ChatGPT的场景；属于依据代码和需求的设计判断，尚非真实负载测试结论。

先前方案的核心已经接近这一组合，但“写后使受影响域失效”过于笼统，可能被实现成每笔写后重新拉取；“60秒缓存”也可能被误解为数据到期删除、定时刷新或统计结果只能缓存60秒。本次明确分层，并补空结果、时间戳和异步回执乱序的契约。

## 3. 逐项取舍

| 项目 | 采用规则及原因 |
| --- | --- |
| 页面展示 | 沿用APK先读本地；Web可先呈现已确认数据并注明陈旧/正在更新，上游失败不清空。MCP按默认检查策略返回结果或任务状态，不能把旧值称作刚从上游验证。 |
| 普通远端检查 | 保留60秒按需检查相关域/查询，不照搬APK的1–12小时页面时长。APK中单个页面变更会更新同机数据库；手机的本地事件不会直接通知Worker，较长时长会放大跨端延迟。60秒也不是自动同步周期或实时保证。 |
| 检查范围 | 账单/标签按各自增量协议；其他资源只取本用例缺失、过期或确需核验的部分，不把一次查询变成刷新全账号。 |
| 写后更新 | 优先应用已核对的官方回执及APK本地变更算法，只让受影响的派生结果失效。回执不足、依赖变化或结果不明才读取核验，不因每笔记账直接清整域缓存。 |
| 统计/日历/预算执行 | 缓存键为规范化参数、实际业务日期/范围、时区、目标币种及依赖数据修订。源数据检查无变化时可继续复用，不按60秒重算；跨日/跨期仍须换键。 |
| 空结果 | 用“该查询已完整获取”的标记识别有效空集合；不能把空列表等同未加载。比照搬上述APK空列表分支更能避免无预算/无计划的重复请求。过滤结果为空只更新该查询成员，不能删除其他范围的实体或声称全域已校验。 |
| 时间与修订 | 完整源检查更新validatedAt，实际业务变化更新changedAt/数据revision；本地查询、状态读取和单条写入不刷新整个域的validatedAt。无变化的增量检查不无故使分页和统计缓存失效。 |
| 并发与恢复 | 保留DO共享任务、按页事务、UID/数据集隔离、持久写键和重建切换。HTTP及alarm环境需要这些机制，Android单进程回调不能代替它们。 |
| 异步旧响应 | 资源读取记录开始时的UID/连接代次、目标数据集和资源失效/写入代次；应用时不匹配则忽略旧响应并保留必要失效状态。避免慢查询盖掉稍后确认的写入，不新增历史版本库。 |
| 状态依赖操作 | 暂停、归档、绑定、结清仍绕过展示缓存，按最新状态与具体packId决策；不把APK较长列表时长当成写入前置依据。 |
| 图片/法定工作日 | 上传token遵循实际到期前60秒余量；法定工作日按官方年份资料及其已验证更新条件缓存，不能统一套业务查询60秒或永不更新。 |

`validatedAt`代表明确查询覆盖范围的成功远端校验，不等同账单协议游标、标签毫秒游标、数据revision或本地修改时间。完整对象回执可以确认该对象；只有明确覆盖整集合的回执才能更新整集合校验时间。接收数据与提升范围完整性在同一短事务内完成。

没有远端推送或后台轮询时，无法保证手机的任意修改立刻出现在Web/MCP。用户明确要求最新或手动刷新时绕过60秒普通检查；账单增量仍遵守5秒冷却并合并任务，不能将其变成清游标全量。没有在途任务时不发请求。

## 4. 实现验收向量

1. t=0完整检查，t=40普通读不请求；t=80普通读启动检查。t=40的读取不续期。
2. 完整空预算/空计划查询在60秒内重复读取不请求；从未获取或分页未完成仍不标为完整空集合。筛选查询为空不清其他资源，列表/详情/选择器看到同一对象更新。
3. t=0全域检查、t=50确认单条写入，t=65普通查询仍须检查；不能把全域校验延至t=110。
4. 完整写回执仅更新目标对象及派生结果，写后立即显示；不固定新增一次全域pull，也不重复叠加资产回执与本地增量。
5. 过期且上游失败保留当前副本并给出陈旧/失败状态，不删除记录，不自动持续重试。
6. 一次增量检查没有业务变化，只提升校验时间；当前有效分页和统计缓存可复用。有实际变化或数据集切换才按依赖失效。
7. 资源读A开始、写B确认、读A迟到：A不能覆盖B；切UID、重建切换和状态依赖对象同样覆盖。
8. 账单修订不变但跨过业务日/账本周期边界时，“今天”、日均可用、相对日期统计采用新范围；不依赖定时上游请求。
9. 多页面与MCP并发读同键只有一个检查；状态查询不另开检查；任务完成后推进时间10分钟无上游请求。
10. Web旧结果需标时间和状态；MCP在10秒期限返回未完成任务信息；不完整账单集合不能重新计算并宣称完整统计。

任务归属：缓存元数据和时序归开发计划08；统计依赖和跨日归10；Web展示与HTTP/MCP行为归11；真实跨端、请求计数和数据延迟归27。
