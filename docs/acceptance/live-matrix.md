## 已发现并修正的实现差异

- 普通新资产必须沿用官方类型的默认图标，并补齐原生新对象的数字默认字段；修改后的三项独立新建均成功。尚未单独隔离各字段的因果关系，因此不把首个失败归因于唯一字段。
- 官方资产类型目录与个人资产来源分开缓存。未核清的个人写入不能使官方类型反复读取。
- `needsValidation` 与对外 `stale/complete` 分开：最近已校验的来源继续遵守60秒窗口，未知操作仍保留，不因读取被清除。
- 5秒同步冷却内可以复用已完成的实际来源检查；每个核查器仍验证该检查晚于原操作及记录内容。明确失败、运行中的检查、过期或未来时间不会被当成证明。
- 成功回执先持久化，再原子应用。解析失败后修复可重解析已收到的回执，禁止再次发送；已提交的部分成功不重应用。历史回执重解析会使当前来源重新校验，不能冒充最新数据。回执只保存在内部操作记录，不通过 Web/MCP 公开原始内容。
- 存钱新建未指定图标表示采用官方默认；现有图标的清空仍有明确未核验限制。顶层模式与规则模式不能矛盾，兼容旧数据仅在 rule 内存储 mode 的形式。
