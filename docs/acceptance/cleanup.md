2026-10-19，用户明确要求最终核对通过后删除全部生成的测试数据，包括测试账本。严格类型、完整后端与桌面/手机回归、生产构建及 dry-run 通过后执行。本次没有修改现用账本或现用资产。

先删除计划和借贷资产，再删除测试账本及普通资产，最后删除标签/分组。13个不同删除操作最终均成功；两项借贷删除的关联账单核查先部分成功，再只读同步确认成功，没有重发。账本删除按原生语义处理，不用补记余额调整清理测试现金中的早期0.07差额；该专用现金资产本身已删除。

删除后，重新读取全部账本、普通/隐藏资产、借入/借出已结和未结目录、资产组、周期、分期、存钱及完整标签组，并再做增量同步。另一次 `cleanup-verify` 只读复查得到：

- 已登记且仍存在的测试管理对象：**0**；同前缀但未登记对象：**0**。
- 测试账本内剩余有效账单：**0**；测试周期、分期及存钱计划均不存在。
- 非测试资源 ID 清单前后完全相同；复查发送业务写请求：**0**。

目录缺席来自完整官方响应，不以本地缓存为空代替删除证明。测试账本删除包含其账单、分类和预算的原生生命周期；没有对个人分类/预算发送批量删除。

## 防止删错的依据

删除集合只取私有验收清单中保存的新建 ID，不按名称前缀批量删除。清理前检查测试账本关联的资产、非测试账单对测试资产/标签的引用、计划和分组成员；越出专用范围则停止。所有写入仍通过本机验收范围策略和生产协调器，使用稳定请求键、当前官方版本及原结果核查。

早期存钱计划因默认图标兼容问题没有成功登记。清理仅补录该计划的来源证明：原命令只发送一次，完整创建前目录为空，当前账号相同，名称、币种、模式、金额、起止规则、备注及颜色与不可变原命令一致，图标是已核对的官方默认值，且没有存入记录。此证明只授权清理其 ID；原新建操作仍保持未知，没有伪造成功或重新发送。

清理工具独立审查发现两项问题，删除前均已复现修复：存钱计划清理强制 `deleteBills=false`，避免刷新后出现的新关联账单被连带删除，账单仅由已证明的新测试账本处理；周期/分期删除前刷新版本，且只有明确 `sendCount=0` 的版本准备失败可建立一次有限的新意图，已发送或未知原操作绝不换键重发。另修复只读检查误将普通账本/资产当作含计划 data 的对象；当时未发送任何删除。最终清理保护回归10项，完整后端491项通过。

## 保留的历史与附件边界

旧未知操作、创建证明和清理审计记录保留在忽略的私有本机状态中，不属于当前账号中的活动测试账务资源。没有为消除历史提示擦除日志、重新发送旧操作或清空个人数据库。原始报告保存在忽略的 `.artifacts/acceptance/cleanup-execute.json` 和 `cleanup-verify.json`，不随 Git 上传。

测试账单图片及测试账本封面引用随所属测试数据移除。APK `AddBillImagePresenter.removeImage` 只取消本地任务并移除选择项；本轮未找到可验证的远端图片对象永久删除接口，也没有尝试猜测存储桶删除请求。因此**不承诺钱迹图片服务器/CDN 的底层测试文件已被永久擦除**。证据见[最终 APK 核对](../research/2026-10-19-apk-final-implementation-check.md)。
