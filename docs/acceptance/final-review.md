# 整支独立审查与修复

2026-10-19。独立审查固定范围：`sanitized-history..sanitized-history`。审查者未参与实现、未修改文件、未接触私有凭证或真实业务数据。按已确认流程仅进行这一次整支审查，主实现者随后统一验证与修复。

确认四项 P2：

| 问题 | 修复 | 复现与验证 |
| --- | --- | --- |
| 已保存的新建回执，被后续来源回读误判为旧 ID，原操作持续未知 | 发送前保存已知资源 ID；借贷另保存已知初始账单 ID。仅在回滚事务验证历史回执时使用该证明，提取操作结果而不发布历史实体 | 资产原回执→较新官方实体先载入→核查成功，零重发、较新字段保留；真实旧 ID 后来删除也仍拒绝认领；八类入口跨重启证明测试 |
| 规范实体中的历史账本/分类被当作完整当前选项 | 账本、分类、标签及转账账本选项读取对应来源成员；未查询、失效或不完整范围不能标完整，规范实体保留给历史解析 | 完整来源移除项目→选项消失、旧实体仍保留；部分分类来源使选项不完整；转账选项同步移除账本 |
| 概览把资产币金额标为原币 | 复用账单页的金额与币种选择器，显示原币录入标识 | 普通外币、有优惠、无关联资产三种账单；桌面/手机概览与账单页一致 |
| 信用卡还款接受普通现金等资产为目标 | 共用领域构造器要求目标 type=2，覆盖预览/新增/编辑；页面只提供信用卡目标 | 现金、储值、投资等目标发送前拒绝；信用卡与普通转账仍可构造；桌面/手机选择器 |

上述缺陷均先得到失败断言，再验证修复。其余增强保护测试首次运行通过，不将其冒充失败复现。旧操作没有发送前证明时仍按原来的保守核查处理，不反向补造证明或根据同名认领。

新增借贷记录的已知账单 ID 证明只扫描 ID，不读取原始账单或重新全量同步；这一步随现有账单数量增长，普通记账不执行该扫描。尚未测量大账单量下生产 CPU。
